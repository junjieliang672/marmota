# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Shell Scripts

| Script | Purpose |
|--------|---------|
| `build.sh` | The one command to install and build. On a Mac with no Go, or nothing in a shell config that runs Marmota, it hands over to `install-deps-macos.sh` (which calls back with `Y_BUILD_ONLY=1`); `--install [args]` forces that, `--no-install` skips it. Otherwise: builds `./bin/y` (the binary is `y`), deletes old `spf` binaries that say they are Marmota, writes the `# >>> y (Marmota) >>>` block in the shell configs that ran Marmota (PATH + the `y` function for cd on quit; an old `Superfile cd-on-quit wrapper` block and `alias y='spf'` are taken out, the file backed up), runs `--fix-config-file`, then on a Mac `./setup-macos-hotkeys.sh --micro`: micro as the editor (Marmota's and `$EDITOR`) and Marmota's block in `~/.wezterm.lua`, brought up to date on every build, so a computer is ready once Marmota is built on it. |
| `dev.sh` | Full dev workflow - runs `go mod tidy`, `go fmt`, `golangci-lint`, tests, then calls `build.sh`. Use `--skip-tests` to skip tests, `--testsuite` for integration tests. |
| `install-deps-macos.sh` | macOS setup, run by `build.sh` the first time - installs Homebrew, Go, tmux, optional deps (exiftool, zoxide, ffmpeg, bat, mupdf, fzf), NvChad, WezTerm, Nerd Font, builds through `build.sh`, configures shell integration for bash/zsh/fish, then runs `setup-macos-hotkeys.sh` (only `--neovim --marmota --cmd-k --micro` when `~/.wezterm.lua` exists). |
| `setup-macos-hotkeys.sh` | Configures WezTerm hotkeys and Marmota editor settings (micro for `e`, in Marmota's place, and in a new tab for `E`), and installs `gy` for nvim (`scripts/nvim/spf_yank_ref.lua`: yanks `@file#L12-15` references). `--neovim` does only the last. `--cmd-k` only makes Cmd+K (WezTerm's Clear) leave Marmota alone in an existing `~/.wezterm.lua`. `--micro` (part of the default run, and what `build.sh` runs) makes micro Marmota's editor: installs it and the tools its searches run (fzf, ripgrep, bat, universal-ctags), merges `scripts/micro` (settings, keys) into `~/.config/micro` (your other keys stay; one Marmota sets is Marmota's, the file backed up), installs the `marmota`, `jump` and `MicroOmni` plugins, sets `editor = "micro"` and `E` to micro in a new tab while those are still the nvim defaults, and writes `export EDITOR="$HOME/.config/micro/plug/marmota/edit"` in a block of its own in `~/.zshenv` (`configure_shell_editor`; an `EDITOR` of your own there stays, unless it is nvim), so Claude Code's ctrl+G opens micro. `--wezterm-look` writes Marmota's block in `~/.wezterm.lua`: its look, and the Mac keys sent to micro, only while micro is the pane's program: the terminal's foreground job, or what tmux says the window a pane's tmux client shows runs (`in_editor`, `program_of`, `tmux_shows`); and, while the pane's program is Claude Code (`in_claude`), option+backspace as alt+backspace and option+delete as alt+D, the keys its input box deletes a word for by the words it moves by (for ctrl+W, which option+backspace is often set to send, it deletes back to a space: a whole Chinese sentence). |

## Build & Development Commands

```bash
# Quick build (detects user's binary location)
./build.sh

# Development workflow (format + lint + tests + build)
make dev          # or ./dev.sh

# Build only (skip tests)
make build        # or ./dev.sh --skip-tests

# Run tests
make test         # or go test ./...

# Run linter
make lint         # or golangci-lint run

# Run full testsuite
make testsuite    # or ./dev.sh --testsuite

# Format code (required before PR)
go fmt ./...

# First-time macOS setup (installs all dependencies)
./install-deps-macos.sh

# Configure hotkeys only
./setup-macos-hotkeys.sh
```

## Architecture Overview

Marmota is a terminal file manager built with [Bubbletea](https://github.com/charmbracelet/bubbletea) (Elm-inspired TUI framework).

### Entry Points
- `main.go` - Embeds config files, delegates to `cmd.Run()`
- `src/cmd/main.go` - CLI setup via `urfave/cli`, creates `tea.Program` with `internal.InitialModel()`

### Core Package Structure

| Package | Purpose |
|---------|---------|
| `src/internal` | Main model, file operations, key handling, search logic |
| `src/internal/common` | Shared config state, styling, hotkey management |
| `src/internal/ui` | UI components (jump: the s list; metadata, processbar, prompt; sidebar and zoxide: the data the s list holds) |
| `src/internal/ui/rendering` | Renderer system for file panels with borders/truncation |
| `src/config` | Fixed variables (paths, versions), type definitions |
| `src/pkg/file_preview` | File preview (syntax highlighting, images, PDFs) |
| `src/pkg/claudesession` | Finds Claude Code sessions: live ones from `claude agents --json`, details and history from `~/.claude/projects` transcripts |
| `src/pkg/claudeask` | The Ask box's requests: the context block, and the permission mode, model and effort flags |
| `src/pkg/words` | The words of a text as the system finds them (the Mac's CFStringTokenizer, through cgo; elsewhere `Supported` is false and callers keep their own rule), so moving and deleting by word stop inside a Chinese sentence: `Left`, `Right`, and `UpdateField`, which every text field's Update goes through. `y words <line>` prints them for micro's plugin |
| `src/pkg/codexsession` | Codex CLI sessions, in claudesession's form: the Codex server's list, state, sending, renaming and interrupting (JSON-RPC over a WebSocket on `~/.codex/app-server-control/app-server-control.sock`), and each session's rollout (conversation, changes) |

### Bubbletea Pattern

The app follows Model-Update-View:
- `src/internal/type.go` - Main `model` struct with all state
- `src/internal/model.go` - `Update()` and `View()` methods
- `src/internal/model_msg.go` - Message types for async operations

Key message types: `PasteOperationMsg`, `DeleteOperationMsg`, `FilePreviewUpdateMsg`, `MetadataMsg`, `GitStatusUpdateMsg`

### File Operations
- `src/internal/file_operations.go` - Copy, move, delete, trash operations
- `src/internal/handle_file_operations.go` - Handlers for paste/delete/compress/extract
- Async operations run in goroutines with progress tracked via `processbarModel`

### Search System
- `src/internal/search_stack.go` - Hierarchical search with layers (regular, recursive, filter)
- Supports file type filters: `f:` for files, `d:` for directories

### Configuration
- User configs: `~/.config/marmota/` (config.toml, hotkeys.toml, theme files)
- Embedded defaults: `src/superfile_config/`
- State files: `~/.local/state/Marmota/`

## Testing Claude session features

- Unit and model tests never run the real `claude` CLI: `TestMain` in `src/internal/model_test.go` swaps in a fake runner, and makes the WezTerm and clipboard seams fail unless a test fakes them (`newFakeWezterm`, `newFakeClaudePane`).
- `python3 testsuite/live/tmux_sessions_test.py --binary <new y> --old <y built from before tmux>` upgrades a real Marmota with sessions open to sessions in tmux, then has WezTerm lose it, in a tmux server of its own (`MARMOTA_TMUX_SOCKET`).
- `python3 testsuite/live/wezterm_sessions_test.py --binary ./bin/y` drives a real Marmota (sessions in WezTerm panes: `MARMOTA_NO_TMUX=1`) inside WezTerm, in a workspace your window doesn't show, with a fake `claude` from `testsuite/live/fakes/`. Its sessions draw a prompt box like Claude Code's (`fake_prompt.py`), since Marmota reads it before typing into a session.
- `python3 testsuite/live/micro_plugin_test.py --binary ./bin/y` runs the real micro with `scripts/micro` (settings, keys, the `marmota` plugin) in a tmux server of its own, against fake `claude` sessions reached through the real `y session`: the Mac keys as the bytes WezTerm sends for them, the column sessions are asked in (its box, the list of sessions and its filter, starting a session, cmd+K, a click or enter on a question going back to its lines, the column put away and in another tab), cmd+G and cmd+shift+G, the wheel during a drag as the mouse reports a terminal sends, cmd+H and cmd+W, the keys of micro's own that the page of keys names, and, with the real Marmota opening micro, the editor put away with cmd+M, brought back with `b`, and ended or brought back by `q`. It needs tmux, micro and fzf, and no WezTerm.
- The tutorial's screenshots (`docs/shots`) are real sessions on demo projects; `testsuite/shots/README.md` says how to retake them without your own sessions or machine showing. The Sessions box's Remote section shows the demo's own sessions there: `MARMOTA_APP_SESSIONS_FILE` names a JSON file of them that is read in place of asking claude.ai (`appSessionsFromFile`).

## Platform-Specific Notes

- macOS: Uses Finder via osascript for trashing protected files
- Windows: Not fully supported yet
- Trash: XDG trash on Linux, ~/.Trash on macOS, trash-go on Windows

## Running it

The binary is `y` (it was `spf`). `y` in a shell is the function `build.sh` writes, which runs `<repository>/bin/y`; there is no alias.
