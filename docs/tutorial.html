Getting Started with Marmota
A tour for your first session

Getting started with Marmota

Marmota is a terminal file manager that works beside your Claude Code and Codex sessions; you start it with y. You browse files on top; at the foot you see every session that runs, what each one is doing, and you can write to any of them without leaving your files.

You need a Mac, WezTerm (y shows sessions in its panes), tmux (sessions run in it, so they outlive WezTerm) and micro (the editor e opens; build.sh installs both), and Claude Code, the Codex CLI, or both.

1

Install it and start it

# the first time, build.sh installs everything: Go, tmux, WezTerm, a Nerd Font, the y command
git clone https://github.com/junjieliang672/marmota.git
cd marmota
./build.sh

# then, in a new terminal (WezTerm)
y

build.sh builds the program into bin/y, adds a short block to your shell config that puts it on your PATH, and gives WezTerm its look: the pane you type in stays bright and a blue edge marks it. It makes micro your editor, with the Mac's keys working in it as in any text field (see Write in the editor). It also installs a skill that tells Claude Code about y session (see Sessions on other computers). Run ./build.sh again whenever you pull new changes; it keeps your settings and adds any new ones.

2

What is on the screen

A

File panels. Your folders. tab moves to the next panel, n opens another. A ✳ marks a file a running session changed.

B

Preview. The file under the cursor; while you are in the Sessions box, the selected session's conversation.

C

Sessions box. Every running session, cc for Claude Code and co for Codex. s goes to a session that needs you or replied since you looked, and again to the next; with none, to the first. esc goes back. Under them, with a cloud, your sessions on other computers.

D

Details. The file, your Mac's cpu, memory and disk, and file operations under way. M focuses it.

E

Ask box. Where you write to a session, or start a new one. K opens it.

F

Status line. The keys you can press now, how many sessions are working, need you or have unread replies, and the time. F hides the boxes at the foot.

Workflow 1

Just browse files

No agents needed. Marmota is a file manager first: two or more panels, a preview of what is under the cursor, and the boxes at the foot, which F hides.

Jump to a project and open a file

  1. z, type part of the folder's name, enter: the first match, the row with the cursor. (ctrl+n opens it in a new panel instead.)
  2. / and a few letters filter the folder; esc clears it.
  3. e opens the file in the editor, in Marmota's place until you close it (more on it below); E opens it in a new tab.

Move files between two folders

  1. n opens a second panel; go to the destination there.
  2. tab back to the first panel.
  3. One file: ctrl+c to copy or ctrl+x to cut. Several: space on each, then c or x.
  4. tab to the other panel, v to paste.

Find a file deep in a folder

  1. Put the cursor on the folder and press f.
  2. Type part of the name; enter goes to the file.

Look before you open

  1. The preview shows text, code, images and PDFs; ctrl+f hides or shows it. In a PDF, alt+shift+→ turns the page.
  2. M focuses Details: the file's size and dates, file operations under way, and your Mac's cpu, memory and disk.

Hand files to another app

  1. p copies the path; P the parent folder's; c the current folder's.
  2. Y puts the selection on a shelf at the right edge of the screen, to drag into a browser or a chat.

Keep your places, and leave from one

  1. t pins the folder under the cursor. z lists your pins, sessions, the folders you visit most and the files you edited lately, in the panel's place; the preview shows the one enter would go to. ↓ picks one, and t, r, p act on it as they do in a panel.
  2. Q quits and leaves your shell in the folder you were in.
Workflow 2

One coding agent beside you

Claude Code or Codex shows in a WezTerm pane next to Marmota, in the folder you are in. You browse on the left and talk to it on the right; Cmd+Opt+← → move between the two. The session itself runs in Marmota's tmux: close the pane, or WezTerm, and it keeps going.

Start it

  1. Go to the project's folder.
  2. >, type claude or codex, enter. The session opens beside Marmota.

Show it the files you mean

  1. Select the files in Marmota (space), or leave the cursor on one.
  2. @ types them into the session's prompt as mentions and moves the keyboard there.
  3. Say what to do with them.

Keep browsing while it works

  1. A ✳ marks each file it changed; a folder shows how many inside (✳3). Git's letter shows beside changed files.
  2. The status line says ✳ 1 working until it replies.

Talk to it without leaving your files

  1. m on a file adds it to your draft as a mention.
  2. K opens the Ask box, which writes to it; type and press enter. ↑ brings back what you said before.
  3. shift+enter is a new line; ctrl+g writes a long question in the editor and brings it back, unsent.

Answer when it asks permission

  1. The status line shows ⚑ 1 needs you.
  2. s lands on it; the preview shows its question with the options.
  3. K hands your keys to the question (y, enter, arrows, esc); ctrl+k gives them back.

Bring it to the folder you are in

  1. Browse to another folder.
  2. = moves the session there; the conversation goes on. Claude Code gets its /cd typed in; a Codex session works there from its next turn.
Workflow 3

Several sessions, one beside you

Hand tasks to sessions that run in the background, each in its own folder, while one stays beside you. The Sessions box lists them all; the others keep running in Marmota's tmux, out of sight, until you bring one in.

Start one in the background

  1. s then n: the Ask box writes to a new session in this folder. (With no session running yet, K opens it that way.)
  2. tab picks Claude Code or Codex; ctrl+o the model, ctrl+t the effort (medium unless you change it), shift+tab the permission mode.
  3. Write the task, enter. It starts out of sight and your keyboard stays in Marmota. Its row shows at once; in a folder it hasn't seen, it first asks whether you trust it, and the preview shows that question: K answers it there.

See how each one is doing

  1. s opens the Sessions box. Each row: its state, cc or co, its name, its age, and what it is doing now. A phone beside the age means Remote Control is on: you can follow and answer that session from the Claude app (Claude Code) or the ChatGPT app (Codex).
  2. The preview shows the selected session's conversation; pgup pgdown scroll it.
✳WorkingReplying or running a tool.
⚑Needs youAsks a permission or a question.
●UnreadReplied since you looked.
○WaitingReady for your next prompt.

Swap which one is beside you

  1. In the Sessions box, j k to a session (or 3g for the third). From your files, ] and [ go straight to the next and the previous one.
  2. enter brings it beside Marmota with the keyboard; the one that was there goes on out of sight. Scrolling up in that pane shows that session's own history.
  3. In the z list, enter on a session only puts the Sessions box on it: the pane beside Marmota stays as it is until you press enter there.

Write to any of them

  1. Select a session in the Sessions box and press K.
  2. Write and press enter: Claude Code gets it in its prompt even while hidden; Codex runs it after what it is doing.
  3. For a running Codex session, ctrl+o and ctrl+t change its model and effort from your next message.

Keep one in view while you browse

  1. Select it, press V: the preview stays on its conversation while you move through files.
  2. V again lets go.

Branch, rename, stop

  1. w forks the session into a new git worktree, to try another approach without touching the first.
  2. r renames it; x stops it after asking (the conversation is kept); m mentions a Claude Code session in your draft.
Workflow 4

Review what a session changed

Before you accept a session's work, read what it did, file by file, without opening each one.

  1. s, select the session, W: the panel lists the files it changed.
  2. Move through them; the preview shows each file's diff. ] and [ jump to the next and previous change.
  3. e opens the file in the editor to fix something yourself, or to ask the session about it from there (cmd+L); K writes to the session from here.
  4. W or esc goes back to the folder.
Workflow 5

Write in the editor, and ask from it

e opens the file in micro, in Marmota's place. It is an editor without modes: you type, and the Mac's keys (cmd+S, cmd+Z, cmd+←, shift+option+→) do what they do in any text field. A column on its right asks your sessions about what you are writing. cmd+H lists every key; cmd+W closes the file, and the last one the editor.

Ask about the lines you are on

  1. Select the lines (shift and the arrows), then cmd+L: a column opens on the right, with the cursor in the box at its foot.
  2. Write the question; enter sends it (shift+enter is a new line, esc goes back to the file and keeps what you wrote). It goes to the session the Ask box wrote to, with the file and the lines named, so the session reads them itself.
  3. The cursor is back in the file: go on writing. The reply shows above the box; cmd+enter puts it at the cursor, or in place of what is selected.

Have a session change the lines

  1. Select them, cmd+K, say what to change, enter.
  2. The session edits the file itself; the editor shows the change when it is made, and cmd+Z takes it back.

Pick another session, or start one

  1. cmd+shift+L lists this Mac's sessions above the box, ✳ for Claude Code and ◆ for Codex. Type to filter them, ↑ ↓ to move, enter to pick.
  2. The first two rows start a new session with your question, in Claude Code or in Codex. It is the editor's own: the Sessions box leaves it out, and it closes when the editor does.
  3. A session that stops to ask you something says so in place of its reply. cmd+O opens it in a pane under the editor; answer there, then close that pane.

Put the editor away, and come back

  1. cmd+M: micro stops as it is, with its files, tabs, undo history and replies, and you are back in Marmota. The status line says so: ✎ micro · 1 file · b back.
  2. b brings it back. A question you asked before goes on being answered meanwhile, and its reply is there when you return.
  3. q with the editor put away ends it first when nothing in it is unsaved, and brings it back when something is.

Move through a file

  1. cmd+G goes to a place: a line's number and enter, or one key, t top, b bottom, p the next paragraph, m the matching bracket. cmd+shift+G selects up to it.
  2. cmd+P opens another file by name; with several open, option+, and option+. go to the tab before and after.

Words, in any language

  1. option+← → move by word and option+backspace deletes one, here and in every text field of Marmota.
  2. A Chinese sentence has no spaces, yet isn't one word: the words are the ones the Mac itself finds, and deleting takes exactly what moving goes over.
Workflow 6

Leave them running

Get on with something else, in Marmota or another app. Marmota tells you when a session needs you, and never moves your focus on its own.

  1. When a session you can't see asks something, fails, or replies, a note appears in Marmota's top right corner; while Marmota isn't in front, WezTerm also posts a macOS notification.
  2. The status line keeps count: ✳ working, ⚑ needs you, ● unread.
  3. s opens the session the note is about; answer it with K, or esc to put the note away.
  4. Away from your desk? Start the session with >claude rc: Remote Control lets you follow and answer it from the Claude app.
  5. Quit WezTerm, or let it crash: the sessions keep running in tmux. Open WezTerm, run y, and every one of them is back in the Sessions box; enter shows one beside Marmota again.
Workflow 7

Sessions on other computers

Run a session on another machine, a Mac mini in the next room or a server you reach over ssh. It runs in Marmota's tmux over there, so it keeps going when your connection drops, and with Remote Control: the Sessions box lists it under this Mac's sessions, with a cloud, as the Claude app lists it, and you go on with it in the Claude app.

Start one there

  1. Ask a coding agent in one of your sessions, in your own words: "open a session on my Mac mini in ~/proj that fixes the flaky test". The skill build.sh installed tells it how.
  2. Or run it yourself: y session start --on "ssh me@192.168.1.20" --cwd ~/proj -- "fix the flaky test". --on is how you reach the machine from a terminal: ssh, ssh -J through a jump host, or a company CLI such as "corp ssh gpu-1 --".
  3. Marmota remembers the machine from then on and keeps one connection to it. With ssh, you log in once for everything.

Follow it from the Sessions box

  1. Under this Mac's sessions, the box lists your sessions on other computers as claude.ai has them, the latest first, each with a cloud: how it stands, and what it waits for. The list is read again every 15 seconds.
  2. enter on one opens it in the Claude app (on claude.ai without the app), where you read it and answer it. The other keys say so.
  3. One whose computer is offline shows greyed. When claude.ai can't be reached the last list stays, greyed, with why; login expired: run claude means running claude once renews the login.

From a terminal, or an agent

  1. y session list lists every session, here and there, who runs it and what it is doing.
  2. y session send id "and add a test" writes to one; y session read id prints its last turns; y session ask sends and waits for the reply.

Bring in sessions already running there

  1. y session adopt --on "ssh me@192.168.1.20" --list lists the sessions someone started there outside Marmota.
  2. y session adopt --on "ssh me@192.168.1.20" name moves one in (no name moves them all): it stops where it ran and goes on with the same conversation, permission mode, model and Remote Control in Marmota's tmux.
4

Make it yours

  • y path-list prints where your settings live, usually ~/.config/marmota.
  • config.toml: your editor (and editor_beside, which opens it in a pane on Marmota's right instead of in its place), theme, preview settings, codex_command, and cd_on_quit (your shell moves to the folder you quit in).
  • hotkeys.toml: every key. If you prefer Vim keys, copy src/marmota_config/vimHotkeys.toml over it.
  • Themes: set theme to the name of any file in the theme folder.
